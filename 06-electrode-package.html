    Package Overview

    The ELECTRODE package implements constant potential, constant charge, and thermopotentiostat methods for electrode-electrolyte simulations. It was developed by Ahrens-Iwers, Tee, and Meissner and first released in LAMMPS 4May2022.

    Key capabilities: - Enforce fixed electrostatic potential on electrode groups - Compute induced charges as function of geometry and electrolyte - Track fluctuating potentials in constant charge mode - Model thermal fluctuations (Johnson-Nyquist noise) in electrochemistry

    Requirements: - KSPACE package (must be enabled) - LAPACK and BLAS (or -D USE_INTERNAL_LINALG=yes with CMake)

    Installing the ELECTRODE Package

    With CMake

    cmake -B build -S . \
  -D PKG_ELECTRODE=yes \
  -D PKG_KSPACE=yes \
  -D USE_INTERNAL_LINALG=yes
cmake --build build

    Note: The ELECTRODE package requires the KSPACE package to be enabled as well, because it relies on the kspace solvers for the electrode-electrode and electrode-electrolyte interaction matrices.

    Verifying Installation

    lmp -h | grep electrode

    Should show ELECTRODE in the list of installed packages.

    The Three Fix Styles

    fix electrode/conp — Constant Potential

    Purpose: Hold the electrostatic potential on each electrode group fixed; charges fluctuate to maintain the constraint.

    Physical meaning: Models a potentiostat — the voltage is controlled, charge is the response. This is what you want for comparing to electrochemical experiments.

    Syntax:

    fix fxconp groupName electrode/conp potential eta keyword value ...
    Argument Description Typical Values
    groupName Electrode group to constrain Must exist before fix
    potential Electrode potential in volts -2.0 to +2.0 V typical
    eta Gaussian smearing width (Å⁻¹) 1.0–2.0 (real) or 0.2–0.5 (metal)

    Complete example:

    fix fxconp bot electrode/conp -1.0 1.805 couple top 1.0 symm on

    Keywords:

    Keyword Description Values
    couple Add additional electrode at specified potential groupName V
    symm Enforce total electrode charge neutrality on or off
    algo Solver algorithm mat_inv, mat_cg, cg
    etypes Use type-based neighbor lists on or off
    ffield Finite-field mode (periodic z) on or off
    write_mat Write capacitance matrix to file filename
    read_mat Read capacitance matrix from file filename
    write_inv Write elastance matrix to file filename
    read_inv Read elastance matrix from file filename

    Dynamic Potential Control

    Any equal-style variable can be used for potential. This enables:

    Linear sweep (cyclic voltammetry-like):

    variable V equal ramp(-1.0, 1.0)
fix fxconp bot electrode/conp v_V 1.805 couple top 1.0

    Sinusoidal (AC perturbation):

    variable V equal "2.0 * sin(time * 0.01)"
fix fxconp bot electrode/conp v_V 1.805

    Stepped potential:

    variable V equal 0.5
fix fxconp bot electrode/conp v_V 1.805 couple top -0.5
run 10000
variable V equal 1.0
run 10000

    fix electrode/conq — Constant Charge

    Purpose: Set the total charge on each electrode group; potentials fluctuate.

    Physical meaning: Models a galvanostat — charge injection/extraction is controlled, voltage is the response. Use when you know the charge dynamics rather than voltage.

    Syntax:

    fix fxconq groupName electrode/conq charge eta keyword value ...
    Argument Description Notes
    groupName Electrode group to constrain Must exist before fix
    charge Total charge on electrode group In units consistent with units setting
    eta Gaussian smearing width Same units as conp

    Complete example:

    fix fxconq bot electrode/conq -0.5 1.805 couple top 0.5 symm on

    Output: The vector component f_fxconq[2], f_fxconq[3], etc. gives the actual potential on each electrode — can be monitored to compute voltage response.

    Accessing potentials:

    variable V_bot equal f_fxconq[2]
variable V_top equal f_fxconq[3]
fix print all print 100 "V_bot = $(v_V_bot), V_top = $(v_V_top)"

    fix electrode/thermo — Thermopotentiostat

    Purpose: Add thermal fluctuations (Johnson-Nyquist noise) to both potential and charge.

    Physical meaning: Models the thermodynamic consistency of charge/potential fluctuations. Essential for fluctuation-dissipation studies, non-equilibrium dynamics, and realistic finite-temperature electrode behavior.

    Syntax:

    fix fxthermo groupName electrode/thermo potential eta temp seed tau_v keyword value ...
    Argument Description Notes
    groupName Electrode group Must exist
    potential Mean potential Fluctuates around this
    eta Gaussian smearing Same as other fixes
    temp Temperature (K) For thermal noise amplitude
    seed Random seed Must be set for reproducibility
    tau_v Potential relaxation time ~50 fs typical

    Complete example:

    fix fxthermo bot electrode/thermo -1.0 1.805 300.0 12345 50.0 symm on

    Physical basis: The fluctuation-dissipation theorem relates thermal noise to dissipative properties. For electrochemistry, the thermopotentiostat adds fluctuations to both potential and charge with correct statistics. This is important for: - Understanding noise in electrochemical sensors - Modeling electrochemical impedance spectroscopy (EIS) - Studying thermal effects on charging dynamics

    Algorithm Choices

    The algo keyword controls how the capacitance/elastance problem is solved:

    Algorithm Precomputation Memory Speed Electrode Motion
    mat_inv Capacitance matrix C (N²) High Fast Static only
    mat_cg Elastance matrix S (N²) Medium Medium Static only
    cg None Low Slowest Allowed

    Where N = number of electrode groups (not atoms). For two electrodes (bot, top), N=2.

    algo mat_inv (Default)

    How it works: 1. At startup: compute capacitance matrix C and store it 2. At each step: solve q = C · V directly (matrix-vector multiply)

    Trade-offs: - Fast per step (just multiplication) - High memory (stores N×N matrix) - Electrodes must remain fixed (matrix is geometry-specific) - If electrodes move, matrix becomes invalid

    When to use: < 10,000 electrode atoms, static electrodes, need fastest per-step performance

    Memory estimate: For N_electrode_groups = 2, matrix is 2×2 = trivial. For N = 100 (complex geometry), matrix is 100×100 = 40 KB. For N = 10,000, matrix is 10000×10000 = 800 MB.

    algo mat_cg

    How it works: 1. At startup: compute and store elastance matrix S (inverse of C) 2. At each step: solve S · q = V via conjugate gradient (iterative)

    Trade-offs: - Medium memory (same matrix size as mat_inv, but stored differently) - Slower per step (iterative solver) - Can handle slightly larger systems - Still requires fixed electrodes

    When to use: Medium systems where memory matters; limited electrode motion

    algo cg

    How it works: 1. No precomputation 2. At each step: solve full A · q = b via conjugate gradient

    Trade-offs: - Slowest per step (full iterative solve every step) - Lowest memory (no matrix storage) - Required for moving electrodes (charging/discharging dynamics)

    When to use: Electrodes move significantly; very large electrode systems where memory is limiting

    Choosing the Right Algorithm

    # Small static system → mat_inv (fastest)
fix fxconp bot electrode/conp -1.0 1.805 algo mat_inv

# Medium static system → mat_cg (balanced)
fix fxconp bot electrode/conp -1.0 1.805 algo mat_cg

# Dynamic electrodes → cg (only option)
fix fxconp bot electrode/conp -1.0 1.805 algo cg

    K-space Compatibility

    The Rule

    ELECTRODE requires electrode-aware kspace styles that provide: 1. Electrode-electrode interaction matrix 2. Electrode-electrolyte interaction vector

    Standard ewald or pppm will not work — they lack the electrode interaction matrices.

    Compatible Kspace Styles

    kspace_style ewald/electrode 1e-5
kspace_style pppm/electrode 1e-5
kspace_style pppm/electrode/intel 1e-5    # Intel-optimized

    Note: You cannot combine standard pppm with ELECTRODE fixes. You must use pppm/electrode.

    Kspace Modify Options

    kspace_modify slab 3          # 2D Ewald correction (non-periodic z)
kspace_modify one-step        # faster elastance computation; less accurate
kspace_modify force 1e-4     # override tolerance for kspace only
kspace_modify order 5        # PPPM interpolation order (higher = more accurate)

    Key Fix Options Reference

    General Options

    Option Description Values
    algo Solver algorithm mat_inv, mat_cg, cg
    symm Charge neutrality on, off
    ffield Finite-field mode on, off
    etypes Type-based neighbor lists on, off
    couple Additional electrode group groupName V or groupName Q

    Symmetry Mode (symm)

    For capacitor-like systems with two electrodes:

    symm on    # Total electrode charge = 0 (system is neutral)

    With symm on: - electrode/conp: if bot = -1 V, top automatically adjusts to maintain symm - electrode/conq: if bot = -0.5 e/atom, top = +0.5 e/atom

    For asymmetric systems or single electrodes:

    symm off    # No charge neutrality constraint

    Finite Field Mode (ffield on)

    fix fxconp bot electrode/conp -1.0 1.805 couple top 1.0 ffield on symm on

    What it does: - Uses periodic boundary in z (not slab geometry) - Potential difference applied via internal E-field: \(E = V / d\) - No vacuum region needed - Smaller z-dimension possible (saves atoms)

    Requirements: - Must use boundary p p p (fully periodic) - Requires symm on (total charge neutrality)

    When to use: You want smaller cells; better for some geometries; want infinite stack model; no surface effects needed

    Matrix Save/Load

    Since LAMMPS restart files don’t yet save ELECTRODE state, use matrix I/O for restart:

    # Save during run
fix fxconp bot electrode/conp -1.0 1.805 write_inv 1000 filename.elast

# Load at startup
fix fxconp bot electrode/conp -1.0 1.805 read_inv filename.elast

    Why this matters: Without matrix I/O, you must recompute the matrix from scratch on restart, which can be slow for large electrode systems.

    Thomas-Fermi Model

    For real metal response (quantum corrections to simple dielectric):

    fix_modify fxconp tf 0.001    # Thomas-Fermi screening length (Å)

    Physical effect: Adds metallic screening beyond the simple dielectric model. The screening length λ_TF characterizes how charges distribute in a real metal.

    When to use: Electrode is a real metal (Au, Pt, Ag) and quantum effects matter for your application.

    Output from ELECTRODE Fixes

    Scalar (Energy)

    f_ID — scalar: the energy added to the system by the fix.

    For constant potential: -Σ q_i V_i (work done by electrodes on the system)

    Check this for energy conservation (should be small fluctuations around constant in NVE).

    Vector (Electrode Potentials and Charges)

    For electrode/conp:

    Index Meaning
    f_ID[1] Energy (same as scalar)
    f_ID[2] Potential on electrode 1 (should match specified)
    f_ID[3] Potential on electrode 2 (if couple used)
    … …

    For electrode/conq:

    Index Meaning
    f_ID[1] Energy
    f_ID[2] Potential on electrode 1 (fluctuates!)
    f_ID[3] Potential on electrode 2
    … …

    Array (Capacitance Matrix Rows)

    f_ID[4] through f_ID[4+N] — rows of the capacitance matrix.

    For a two-electrode system:

    f_ID[4] = C_11 (charge response of electrode 1 to electrode 1 potential)
f_ID[5] = C_12 (charge response of electrode 1 to electrode 2 potential)
f_ID[6] = C_21 (charge response of electrode 2 to electrode 1 potential)
f_ID[7] = C_22 (charge response of electrode 2 to electrode 2 potential)

    Accessing Output in Variables

    # For conp fix named fxconp
variable Q_bot equal f_fxconp[5]    # bottom electrode charge
variable Q_top equal f_fxconp[6]    # top electrode charge
variable E_elec equal f_fxconp[1]   # electrode work term

# For conq fix named fxconq
variable V_bot equal f_fxconq[2]    # bottom electrode potential
variable V_top equal f_fxconq[3]    # top electrode potential

# Print during run
fix printQ all print 100 "Q_bot = $(v_Q_bot) Q_top = $(v_Q_top)"

    Complete Input Script Template

    # ============================================
# Constant Potential Supercapacitor
# Au electrodes, SPC/E water, 1M NaCl
# ============================================

units metal
atom_style charge
boundary p p f

# --- Box and geometry ---
variable Lx equal 20
variable Ly equal 20
variable Lz equal 60

region box block 0 $Lx 0 $Ly 0 $Lz
create_box 5 box    # 1=bot electrode, 2=top, 3=O, 4=H, 5=Na, 6=Cl

region bot block 0 $Lx 0 $Ly 0 5
region top block 0 $Lx 0 $Ly 55 $Lz
region elyte block 0 $Lx 0 $Ly 5 55

create_atoms 1 region bot    # bottom electrode
create_atoms 2 region top    # top electrode
# (Water and ions added separately - use moltemplate or similar)

group bot region bot
group top region top
group elyte region elyte
group electrode union bot top

# --- Force field ---
pair_style lj/cut/coul/long 10.0

# Electrode-electrode (soft repulsion)
pair_coeff 1 1 0.01 3.0
pair_coeff 2 2 0.01 3.0
pair_coeff 1 2 0.005 3.0

# Water LJ (SPC/E)
pair_coeff 3 3 0.155 3.166    # O
pair_coeff 4 4 0.0 0.0        # H

# Ion LJ
pair_coeff 5 5 0.0874 3.40    # Na
pair_coeff 6 6 0.100 4.45     # Cl

# Cross terms
pair_coeff 1 3 0.005 3.1
pair_coeff 2 3 0.005 3.1
pair_coeff 1 4 0.0 0.0
pair_coeff 2 4 0.0 0.0
pair_coeff 5 3 0.114 3.28    # Na-O
pair_coeff 6 3 0.124 3.81    # Cl-O
# ... all other cross terms needed ...

kspace_style pppm/electrode 1e-5
kspace_modify slab 3

# --- ELECTRODE fix ---
fix fxconp bot electrode/conp -1.0 1.805 couple top 1.0 symm on

# --- Integrators ---
fix frozen all nve           # frozen electrodes
fix mytemp elyte langevin 300.0 300.0 100.0 12345

# --- Output ---
thermo 100
thermo_style custom step temp pe ke vol density f_fxconp[1]

variable Q_bot equal f_fxconp[5]
variable Q_top equal f_fxconp[6]
fix printQ all print 100 "Q_bot = $(v_Q_bot) Q_top = $(v_Q_top)"

dump 1 all custom 100 traj.lammpstrj id type x y z q

# --- Run ---
minimize 1e-6 1e-9 1000 10000
run 10000

    Troubleshooting

    Issue Cause Solution
    Charge oscillates wildly eta too small or too large Try eta = 1.0 or 2.0 (real units)
    Matrix inversion fails Singular matrix Increase eta or check geometry
    NaN in output Overlapping atoms Minimize before dynamics
    Slow performance Large matrix storage Use algo mat_cg or algo cg
    kspace style not supported Wrong kspace for ELECTRODE Use pppm/electrode
    Energy not conserved Electrode motion with mat_inv Use algo cg or freeze electrodes
