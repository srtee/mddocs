    What Is Being Held Constant?

    Real experiments control temperature, pressure, and composition. In MD, we choose which of these to hold fixed — this determines the statistical ensemble and thus which thermodynamic properties we can legitimately compute.

    Ensemble LAMMPS Fix What’s Fixed What Fluctuates Use Case
    NVE fix nve E, V, N T, P Microcanonical; equilibrium check
    NVT fix nvt or fix npt T, V, N E, P Canonical; most production
    NPT fix npt T, P, N E, V Isobaric; density-sensitive properties
    NPH fix nph P, H, N T, V Isobaric without thermostat (rare)

    The ensemble choice is not just convention — it determines which statistical mechanics formula you must use to connect simulation results to experimental observables.

    Example: If you run NVT and compute the compressibility, you need to use the NVT formula for fluctuations, not the NPT formula. Using the wrong ensemble = wrong physics.

    The Physical Meaning of Temperature

    Temperature Is a Statistical Property

    In MD, temperature is defined from kinetic energy:

    \[T = \frac{2}{3N_f k_B} \sum_i \frac{1}{2}m_i v_i^2\]

    Where \(N_f\) is the number of degrees of freedom (3N minus constraints).

    Key points: - Temperature is a mean quantity — the instantaneous value fluctuates - Fluctuations scale as \(1/\sqrt{N}\) — larger systems have smaller relative fluctuations - For N=1000 water molecules, T fluctuates by about ±10 K even in equilibrium

    Temperature vs. Kinetic Energy

    For an ideal gas, \(T\) is directly proportional to kinetic energy. But in a real system:

    \[T \propto \langle KE \rangle / N_f\]

    This means: - If you increase the timestep and integration becomes inaccurate, KE may “drift” - If atoms are constrained (shake), those degrees of freedom don’t contribute to T - A frozen atom (velocity set to zero) doesn’t contribute to temperature at all

    Why this matters: compute temp uses the actual velocities of atoms in the group. If you thermostat only a subgroup, only those atoms’ velocities contribute to that compute.

    Time Integration and Timestep

    The Velocity Verlet Algorithm

    MD integrates Newton’s equations numerically. The velocity Verlet algorithm is:

    1. Half-step velocity: \(v(t + \Delta t/2) = v(t) + 0.5 \cdot F(t)/m \cdot \Delta t\)
    2. Full-step position: \(x(t + \Delta t) = x(t) + v(t + \Delta t/2) \cdot \Delta t\)
    3. Compute new forces: \(F(t + \Delta t) = -\nabla U(x(t + \Delta t))\)
    4. Complete velocity: \(v(t + \Delta t) = v(t + \Delta t/2) + 0.5 \cdot F(t + \Delta t)/m \cdot \Delta t\)

    Why this order? Because \(F(t + \Delta t)\) depends on \(x(t + \Delta t)\), which is only known after step 2.

    Why Velocity Verlet?

    Property Significance
    Time-reversible Symplectic integrator; conserves phase space structure
    Stable Energy drift is bounded over long simulations
    Velocity explicit Velocities are computed at full timestep (unlike position Verlet)

    Timestep Selection

    The timestep \(\Delta t\) must be small enough to resolve the fastest motion in the system:

    Motion Characteristic Frequency Period Δt Limit
    C-H bond stretch ~3000 cm⁻¹ ~11 fs ~0.5 fs
    O-H bond stretch ~3500 cm⁻¹ ~9.5 fs ~0.5 fs
    H-O-H bend ~1600 cm⁻¹ ~21 fs ~1 fs
    LJ repulsion Very fast ~2–4 fs ~0.5 fs
    Metal phonon ~5–10 ps period ps scale ~1–2 fs

    Typical values:

    System Timestep Reason
    Flexible molecules (methanol) 0.5 fs Fast C-H stretch
    SPC/E water (rigid) 1 fs Fast O-H is constrained
    TIP4P water (rigid) 1–2 fs Fast O-H is constrained
    Metal (Ag, Au) 2 fs Heavy atoms; slow phonons
    with fix shake 2 fs Constrains remove fast modes

    How to check if timestep is too large:

    # Run NVE and check energy drift
fix conservative all nve
run 10000    # 10 ps at 1 fs
# In output, check TotEng drift
# If TotEng changes by >0.1%, reduce timestep

    Bond Constraints

    fix shake removes fast degrees of freedom by constraint:

    fix constrain all shake 1e-4 200 0 a 1.0 b 1.0
    Parameter Meaning
    1e-4 Tolerance for constraint satisfaction
    200 Maximum iterations per step
    0 Which atoms to NOT constrain (none)
    a 1.0 Bond type 1 has length 1.0 Å
    b 1.0 Bond type 2 has length 1.0 Å

    Physical effect: Instead of integrating the fast O-H stretch (period ~9.5 fs), it’s held fixed. This removes the mode requiring small Δt.

    Result: Can use Δt = 2 fs (2× faster simulation) with same accuracy for slower modes.

    Thermostats — Controlling Temperature

    Why We Need Thermostats

    NVE (microcanonical) samples an ensemble where total energy is conserved. But: - Initial velocities are drawn from a Maxwell-Boltzmann distribution at temperature T - As simulation proceeds, numerical errors slightly change total energy - The system doesn’t perfectly sample canonical (NVT) — it’s a quasi-ensemble

    For production, we want true canonical ensemble sampling → use a thermostat.

    Thermostat Algorithms

    Velocity Rescaling (fix temp/rescale)

    fix tempctr all temp/rescale 10 300.0 300.0 0.02 1.0

    Simple scaling: multiply all velocities by a factor to match target T:

    \[v_{new} = v_{old} \sqrt{\frac{T_{target}}{T_{current}}}\]

    Problems: - Does not produce correct fluctuations (variance too low) - Not physically motivated (invented for MD) - Can distort dynamics if coupling too tight

    Use only for: quick equilibration before switching to a proper thermostat.

    Berendsen Thermostat (fix berendsen)

    fix ber all berendsen temp 300.0 300.0 100.0

    Weak coupling to heat bath:

    \[\frac{dT}{dt} = \frac{T_{bath} - T}{\tau}\]

    Problems: - Produces temperature fluctuations that are too small by factor \(\sqrt{2/N_f}\) - Does not sample canonical ensemble correctly - Not recommended for production

    Advantage: very stable; good for systems that are hard to equilibrate.

    Nosé-Hoover Thermostat (fix nvt)

    fix nvt_all all nvt temp 300.0 300.0 100.0

    Extended system method: adds a degree of freedom \(s\) (the “thermostat”) that shares energy with the system.

    The modified Hamiltonian:

    \[H' = \sum \frac{p_i^2}{2m_i} + U(\mathbf{r}) + \frac{Q}{2}\dot{s}^2 + (N_f+1)k_B T \ln s\]

    Where \(Q\) is the ” thermostat mass” (related to tdamp in LAMMPS).

    How it works: - If system is too hot → thermostat absorbs energy (s accelerates) - If system is too cold → thermostat gives energy (s decelerates) - Over time, correct canonical distribution is sampled

    Parameters: - 300.0 300.0 = target temperature and damping source temperature (both same in NVT) - 100.0 = tdamp = coupling time in fs (should be ~100 fs for correct fluctuations)

    Why 100 fs? The characteristic time for energy exchange between degrees of freedom is ~100 fs. Too small = over-damped; too large = slow equipartition.

    Langevin Thermostat (fix langevin)

    fix mylang all langevin 300.0 300.0 100.0 12345

    Stochastic differential equation:

    \[m\frac{dv}{dt} = F - \gamma mv + \sqrt{2\gamma m k_B T} \, \xi(t)\]

    Term Physical Meaning
    \(F\) Conservative force from potential
    \(-\gamma mv\) Friction (damping)
    \(\sqrt{2\gamma m k_B T} \, \xi(t)\) Random noise; \(\xi(t)\) is Gaussian white noise

    Physical interpretation: the system is coupled to a heat bath that: 1. Applies friction (energy dissipation) 2. Supplies random impulses (thermal fluctuations)

    Together, these produce correct canonical sampling (fluctuation-dissipation theorem).

    Parameters: - 300.0 300.0 = target temperature, temperature of heat bath - 100.0 = damping time \(\tau_{damp} = m/\gamma\) - 12345 = random seed (set explicitly for reproducibility)

    Advantages: - Ergodic even for small systems (stochastic component) - Good for non-equilibrium dynamics (shear, external field) - Good for systems with heterogeneous dynamics (some atoms much heavier than others)

    Disadvantages: - Adds artificial friction; modifies dynamics (no “true” Newtonian trajectory) - Inertial effects from friction alter short-time behavior

    Thermostat Comparison

    Thermostat Fluctuations Correct? Ergodicity Affects Dynamics? Best Use
    temp/rescale ❌ No (all same T) N/A Yes (artificial) Quick equilibration only
    berendsen ❌ No (too small) Poor Weakly Not recommended
    nvt (Nosé-Hoover) ✅ Yes Good Weakly Standard production
    langevin ✅ Yes Good (stochastic) Yes (friction) Non-equilibrium; heterogeneous
    npt (with T-chain) ✅ Yes Best Weakly Difficult cases

    For ELECTRODE simulations: Langevin on electrolyte is common because it ensures ergodicity even with constrained electrodes.

    What Temperature Actually Controls

    T Change Physical Effect Observable
    Increase T Higher kinetic energy → faster motion Higher diffusion coefficient
    T too high Bonds may break; chemical reactions System decomposes
    T too low Slow dynamics; metastable states Long equilibration times
    T fluctuations too small Wrong ensemble (Berendsen) Wrong heat capacity

    The diffusion coefficient \(D\) depends on temperature:

    \[D(T) \approx D_0 \exp\left(-\frac{E_a}{k_B T}\right)\]

    For water, \(E_a\) ≈ 0.2 eV, so doubling T roughly doubles D.

    Barostats — Controlling Pressure

    Pressure in MD

    Pressure from virial theorem:

    \[P = \frac{Nk_BT}{V} + \frac{1}{3V}\left\langle \sum_i \mathbf{r}_i \cdot \mathbf{F}_i \right\rangle\]

    Term Physical Meaning
    \(Nk_BT/V\) Kinetic contribution (ideal gas pressure)
    \(\langle \sum \mathbf{r} \cdot \mathbf{F} \rangle / 3V\) Virial from interatomic forces

    For isotropic bulk: this scalar P is appropriate.

    For anisotropic systems (slabs, interfaces): we have a pressure tensor:

    \[P_{\alpha\beta} = \frac{Nk_BT}{V}\delta_{\alpha\beta} + \frac{1}{V}\left\langle \sum_i r_{i\alpha} F_{i\beta} \right\rangle\]

    Where \(\alpha, \beta \in \{x, y, z\}\).

    Barostat Types

    Nose-Hoover Barostat (fix npt)

    fix npt_all all npt temp 300.0 300.0 100.0 iso 1.0 1.0 500.0

    Keywords for pressure coupling:

    Keyword What It Controls Use When
    iso All three components equally Isotropic bulk liquid
    aniso x, y, z independently Anisotropic crystals; allow volume changes in each direction
    semiiso xy coupled, z separate Slab geometry with non-periodic z

    For slab geometries (electrode-electrolyte):

    fix npt_slab all npt temp 300.0 300.0 100.0 semiiso 1.0 1.0 500.0

    This controls P_x = P_y (the periodic directions), but allows P_z to be different (the non-periodic direction). The volume adjusts to satisfy the x,y pressure constraint.

    Why semiiso? In slab geometry with non-periodic z: - x and y are periodic → pressure in those directions makes sense - z has vacuum/fixed boundaries → the pressure tensor component is less meaningful - Allowing P_z to float lets the system find its natural spacing

    MTK Barostat (Martyna-Tobias-Klein)

    fix npt_mtk all npt temp 300.0 300.0 100.0 aniso 1.0 1.0 500.0

    The MTK formulation is more reliable for: - Non-equilibrium systems (with external fields) - Anisotropic stress states - Systems where pressure tensor components matter independently

    What Pressure Controls Physically

    Pressure Change Physical Effect Observable
    Increase P Compress system; atoms closer Lower volume; higher density
    NPT equilibration System reaches correct density Density ~1 g/cm³ for water at 1 atm
    Anisotropic P Different stress in different directions Cell angles change (for crystals)
    P too high Over-compression; atoms too close Density too high; forces too large

    For water at 298 K and 1 atm: expected density ≈ 0.997 g/cm³ (SPC/E gives ~0.98 g/cm³, a known limitation).

    Combining Thermostats and Barostats

    fix npt combines both thermostat and barostat. To use them separately:

    fix mytemp all nvt temp 300.0 300.0 100.0    # thermostat only
fix mybar all npt temp 300.0 300.0 100.0 iso 1.0 1.0 500.0  # barostat only (and thermostat)

    Actually, npt already thermostats. Separate use is rare.

    For ELECTRODE Simulations

    Standard approach for static electrodes:

    fix frozen all nve                  # No dynamics on any atoms
fix mytemp elyte langevin 300 300 100 12345  # Only electrolyte is thermostatted

    Why freeze electrodes? - Most electrode models don’t have realistic dynamics (no phonons, wrong masses) - The ELECTRODE fix computes induced charges, not forces that move atoms - Performance: fewer atoms to integrate

    If electrodes should move (charging/discharging dynamics):

    fix elec_nvt electrode nvt temp 300 300 100
fix elyte_nvt elyte nvt temp 300 300 100

    Or use Langevin on both:

    fix elec_langevin electrode langevin 300 300 100 12345
fix elyte_langevin elyte langevin 300 300 100 12345
    WarningDon’t Double-Thermostat

    If you apply two thermostats to the same atoms, they will fight each other. Use EITHER fix nvt OR fix langevin on a given group — not both.

    Observables — What You Actually Measure

    Thermodynamic Output

    thermo 100
thermo_style custom step temp pe ke vol density
    Variable Physical Meaning Normal Behavior
    Temp Instantaneous temperature Fluctuates ±10 K around target
    PotEng Potential energy Stable; small drift acceptable
    KinEng Kinetic energy Fluctuates with T
    TotEng Total energy Conserved in NVE; drifts in NVT/NPT
    Vol System volume Constant in NVT; adjusts in NPT
    Density Mass/volume Should match experimental ~1 g/cm³
    Press Total pressure Fluctuates; mean matches external P

    Computes for Analysis

    compute temp_elec elyte temp     # Temperature of electrolyte only
compute stress all stress/atom  # Per-atom stress tensor (for local pressure)
compute RDF all rdf 2 * 500     # Radial distribution function g(r)
compute msd all msd            # Mean squared displacement (diffusion)

    Fix-Specific Output (ELECTRODE)

    For fix electrode/conp, the fix stores values that can be accessed:

    variable Q_bot equal f_fxconp[5]    # charge on bottom electrode
variable Q_top equal f_fxconp[6]    # charge on top electrode
variable V_bot equal f_fxconp[2]   # potential on bottom (for conq mode)

    The exact indices depend on the fix configuration. To find them:

    print "Fix values: $(f_fxconp)"

    Trajectory Output

    dump 1 all custom 100 traj.lammpstrj id type x y z q
dump 2 all dcd 100 traj.dcd    # binary format; much smaller files

    Common Mistakes

    Mistake Consequence Correction
    Thermostatting frozen atoms No dynamics (atoms can’t move) Only thermostat mobile atoms
    Using Berendsen for production Wrong heat capacity Use Nosé-Hoover or Langevin
    Timestep too large Energy drift, crash Reduce Δt or constrain bonds
    Forgetting barostat for density Wrong equilibrium density Use NPT to equilibrate density
    Anisotropic pressure for isotropic system Stressed state, wrong density Use iso pressure control
    Coupling time too small Over-damped; slow equilibration Use ~100 fs for NVT, ~500 fs for NPT
    Double thermostatting System fights itself; weird behavior Check fix commands; only one thermostat per group
